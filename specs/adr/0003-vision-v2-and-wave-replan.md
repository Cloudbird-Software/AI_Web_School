## 一、为什么要改宪法（问题陈述）

四份独立审查报告在互不通气的情况下，指向同一个系统性风险：**"宪法说有、代码说没有"的虚假强制层**。典型证据（均已在当前分支复验存在）：

| 宪法条款 | 文档/注释宣称 | 代码实际 |
|---|---|---|
| D1 三本账只增不改 | "DB 触发器兜底拒绝" | `item_version` 有触发器，但 `material_version` / `corpus_version` / `item_template_version` 无 |
| D2 门的数据库级强制 | "发布事务必须持合法门证书，由数据库触发器强制" | 内容表 `gate_certificate_id` **没有 FK**，CHECK 只验非空；服务层也只验非空 |
| D7 PII 隔离 | "LLM/TTS 调用前必须剥离 PII" | AI 总线 PII 剥离 fail-open 且有 `bypass_pii_filter` 开关；TTS 链路不剥离 |
| D7 家长授权 | 合规模块实现完整 | `check_consent` 在线链路零调用方 |
| P4 黄金路径 30 抽样 | 遥测 README 称 "30/30" | `tests/golden-path/` 实际只有 1 个 single_choice 场景 |
| 迁移可逆 | `make migrate-check` | 只 `downgrade -1`，21 个中间迁移的 downgrade 从未验证 |

根因不是某个 bug，而是**宪法条款与可执行实证之间没有强制绑定**：条款写在 L0，实证散落在测试里，没有任何机制保证"每条条款至少有一个会红的信号"。宪法 P3 说"机器信号是唯一事实"，但这次是机器信号本身不够深。

同时，v1.0 宪法只覆盖"内容资产"的正确性，对**在线链路正确性**（认证、事务、幂等、并发）、**AI 可回放**、**增长与成本计量**没有条款。这三块恰恰是从"工程演示"走向"真实用户 + 商业闭环"的必经之路。

## 二、宪法修订清单（v1.0 → v2.0）

| 编号 | 类型 | 内容 | 触发证据 |
|---|---|---|---|
| V1–V6 | 新增第零部分 | 北极星愿景：卖确定性 / 数据飞轮是唯一不可复制资产 / 闭环优先 / 护城河逐层加深 / 单位经济性内建 / 上线即真实用户 | 业务全景说明书；审查报告"对产品愿景的架构评估" |
| A8 | 新增公理 | 宪法即测试（承诺兑现度）：每条条款必须在强制实证矩阵登记可执行实证，无实证=未实现 | 上表六条"说有实际没有" |
| A9 | 新增公理 | 在线链路与内容资产同级（事务/幂等/并发/SLO/降级必须有测试承载） | `record_event` 内部 commit、`submit_answer` 无锁无幂等 |
| A10 | 新增公理 | 增长闭环内建（漏斗/成本/交付状态由系统产出，且不破 D7/D8） | V5/V6 + 成本仪表盘仅覆盖 AI 台账 |

| D10 | 新增铁律 | AI 可回放（模型版本/prompt 版本/成本/关联产物全台账）+ PII fail-closed | 台账盲区、`bypass_pii_filter`、scoring_trace 无 model_version |
| D11 | 新增铁律 | 写路径事务纪律（服务不自 commit、单事务、幂等、审计独立事务） | 事件账与会话状态可分裂；审计日志随业务事务回滚 |
| P9 | 新增纪律 | 实证矩阵常绿：波次出口必须刷新矩阵，缺实证等同黄金路径变红 | A8 的执行机制 |
| X11 | 新增禁令 | 禁止"测试与实现互证"（伪造被测数据形态骗过测试；fixture 预插生产不存在的占位行） | 查重 validator 用 digest 当 ID；`cert:none` 仅测试预插 |
| X12 | 新增禁令 | 禁止合规降级（PII/授权/许可失败必须 fail-closed） | AI 总线注释原文"宁可调少不宁可漏调" |
| X13 | 新增禁令 | 禁止无主体的数据访问路径 | D9 的执行机制 |

**未改动**：A1–A7、D1–D8、P1–P8、X1–X10 一字未动——v2.0 是**增量补强**，不推翻任何既有约束。

| W0–W4 出口脚本 | 不受影响，继续作为不退化基线 | W5+ 出口脚本必须包含 W0–W4 全部不退化检查 |

## 四、波次重规划（W5–W8）

原 W0–W4 的隐含终点是"小程序发布前就绪"，但发布前就绪 ≠ 可发布：认证、事务、合规接入三块是硬阻塞。重规划后的四波（详见 `tasks/roadmap.md` 与各波 `BRIEF.md`）：

| 波次 | 名称 | 一句话目标 | 对应愿景 |
|---|---|---|---|
| W5 | 信任硬化波 | 把宪法从"文档承诺"变成"物理强制"，消除上线阻塞（门/账/认证/合规/事务/测试可信度） | A8/D9/D10/D11 · V2 |
| W6 | 引擎解锁与飞轮加速波 | 解锁"真·无限出题"（学科函数库注入）与 D5/D6 闭环，让飞轮真正转起来 | V2/V3 |
| W7 | 首个真实用户波 | 学生端在线闭环 + 账号/授权/权益/交付 + 可观测运营，跑出第一个真实付费闭环 | V1/V6 |
| W8 | 规模与增长波 | 内容规模化、B 端托管机构、自适应练习、单位经济性达标 | V4/V5 |

排序理由：**先可信、再能力、后规模**。W5 不做完，任何新功能都建立在"可被绕过的门"和"可被冒充的会话"之上，写入的数据反而会污染 V2 的飞轮资产——脏数据比没数据更贵。

## 五、旧 GitHub Issue 裁决（#20–#30）

裁决全文与逐条证据见 `tasks/LEGACY-ISSUES.md`。结论摘要：

- **已完成可关闭**：#25（交互/评分器注册表已在 `specs/contracts/registries/` + `src/registry/loader.py` + `src/core/scoring/` 落地，仅命名口径不同）
- **重复**：#23（是 #20 的 issue body 搬运动作，且交付物不应是 issue body）
- **与架构/合规冲突建议关闭**：#27（RACE）、#30（ASSISTments）——外部题目直导既与 A1/A7「统一入库 + 校验门」路线冲突，也踩合规红线"永不使用真题原文"与商用许可不明
- **部分完成需收敛**：#20（导入契约）、#22（CI/监控）、#29（渲染管线）→ 收敛为 W5/W7 中的具体任务卡
- **有价值需重写**：#24（索引与性能基线）→ W6；#26（受控导入管线）→ W6；#28（CMRC/DRCD 作为**已登记语料**而非直导题目）→ W6

## 六、结论

接受 v2.0 全部修订与 W5–W8 波次重规划。W5 立即启动，其余波次按 P5「波内冻结」原则在启动时把 ISSUES 台账物化为任务卡。
