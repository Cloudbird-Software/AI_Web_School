### 1.2 逐模型评审要点

#### MD —— 排名第 1，作为架构基线

- **唯一提供完整需求追溯矩阵**（§16：M 级需求逐条→机制→章节），7 个专家问题逐一设章作答，S/C 级需求亦注明预留接缝。
- **取舍论证最规范**：§1.2 全部按"选择｜否决项与理由"呈现（如"参数估计：首年 CTT+收缩→次年 Rasch/2PL｜否决第一天就上 3PL：数据量不足、结论不可辩护——测量场景大忌"）。
- **技术判断与首年规模精确匹配**：模块化单体+3 执行器、千级节点拒图数据库、离线 CP-SAT+在线启发式、手写识别降级，几乎无过度设计。
- **诚实边界最清楚**：§13 难点专章；"目标不变不存在通用机器证明，是高置信保障而非证明"；十年纪律"破坏者往往是好心修数据"。
- **估算方法最扎实**：13 个工作流分项 77 人月 + 15% 缓冲 ≈ 89（区间 75–95），7–8 人 × 10–11 个月分两期，M2 设组装引擎抽象 spike 去风险。
- 硬核独有设计：门证书的数据库触发器强制（"任何绕过服务的直写都会被拒"）、CI 跑玩具学科包自证学科边界、完整 DSL 示例（可直接作规范 v1 种子）。
- 弱点：无 NFR/SLO 量化指标；少数 S 级需求仅一句带过。

#### FB —— 并列强参考，洞察密度最高

- 规模判断处处校准精准："周更批处理的真实规模是数十到数百个 SKU 的渲染、数千份分发，单机即可完成"；"图谱 MB 级可直接加载内存按版本缓存"；"20 题内分层抽样+贪心修复即可，无需重型 CP 求解器"。
- 独有真知灼见（均为其他模型未提）：
  - **拆母题纪律**：凡改变考查目标的参数（"求差"改"求减数"实为考逆运算）禁止作变式维度、必须拆成两个母题——用建模纪律换 R-Q-05 的可证性，是对该难点的最深刻处理；
  - **预渲染专项卷库存**：S2"免费发放针对性练习"按错误类型预渲染小卷、诊断出类型即查表发放，把按人实时渲染降级为查表——直接决定 S2 单位经济性；
  - **练习数据暴露偏差**：练习场景因自适应组卷存在选择偏差，只可用于粗校准，正式标定以诊断/测量为准——对 R-Q-24 的最深解读；
  - AQL 加严抽检（抽检失败自动升级同母题/同批次采样率）；二维码只含卷 Spec ID 防爬库；R-K-05"技术易、治理难"；前两个月用 50 个真实母题冻结 DSL v1。
- 诚实边界优秀：明确 R-Q-05 只能"结构保证+求解器验证+统计核验"组合逼近、R-Q-14 补偿关系"学界亦无完备解"、S2 拍照识别是"全案技术风险最高点"。
- 估算合理：净 67 人月、总约 80 人月，8 工程师+1 教研-工程混合角色 × 12 个月。
- 弱点：散文体无追溯矩阵（其推理过程显示这是外部格式约束，非能力缺失）；边缘需求着墨少。

#### GPT —— 并列强参考，严谨度最高、但基础设施需打折采纳

- 独有贡献全场最多，且**发现了两个其他所有模型都没发现的实质问题**：
  1. **需求书内在矛盾**：S4"约 20 题"与 R-Z-03"每知识点≥3 题"在 7 知识点单元时不可同时满足（仅孤立题最低 21 题），并给出三条化解路径；
  2. **曝光互斥语义模糊**：社交媒体公开分发的 PDF 只能保证"批次/周次级不重复"，学生个人级不重复必须记录家庭领取关系——需业务确认。
- 其他高价值独有设计：VariantCertificate（"只有已认证变换算子的实例才能标记受控变式"，AI 自由改写永远只能 UNPROVEN）、置信度四层分离（识别/评分/推断/掌握不得混为一个"AI 置信度"）、authoring/serving 分 schema+数据库角色权限（与 MD 的触发器并列为"物理无法入库"最强实现）、查重第四级"解题结构指纹"（识别只换数字的重复题）、完整的可执行验收指标章（10 万实例重放哈希 100% 一致、绕过发布服务直写必须在 DB 权限层失败等）、instance_key 含学科包/生成器/词库 digest 的最完整可复现链、"Iceberg 时间旅行≠十年归档"的归档纪律。
- **必须打折的部分**：首年技术栈过重——Temporal + 托管 Kafka + Iceberg + K8s + WASM 插件 + Kotlin/Python 双语言，对"数万题、百万作答、数千并发"明显过度（其自身推理过程中也曾犹豫"Iceberg catalog feels like overhead"，最终仍写入）；工程量 130–174 人月为全场最高，且**与其自身思考过程中的 80–120 人月不一致**，估算稳定性存疑。
- 结论：**全部分析性发现与验收标准采纳；基础设施选型不采纳，按 MD/FB 的轻量路线执行**。

#### GK —— 次要参考

- 优点：7 问全覆盖、量级判断大体正确（90–140 人月、8–12 人）、QTI 互通思路与中国云部署考量为独有。
- 不足以列强参考的原因：
  - **选型普遍骑墙**："模块化微服务（或模块化单体起步）""Neo4j 或 Postgres AGE""Kafka/RocketMQ""Temporal/Prefect"——关键决策点缺"否决项+理由"；
  - **混合图存储是设计气味**：千级节点、浅遍历的规模下引入 PG+图引擎双存储与同步一致性负担，三个强参考模型均以同一组规模数据否决图数据库；
  - R-Q-05 以"`invariance_proof`：元数据或钩子"搪塞最难需求；母题模板用 Jinja2/Handlebars，正是 MD 明确论证否决的纯文本模板路线；实例 ID 同时含 seed 与 canonical_params，确定性来源表述混乱；
  - 手写批改仅"专用优化+人工兜底"一句，无强参考模型那样的结构化降级设计。
- 可抽取：QTI 导入导出、组装 rationale 审计输出、公平性监控落点、外部心理测量顾问配置。

#### GLM —— 不作为参考（仅摘取 2 点）

- **致命伤：架构最重 × 估算最低的自相矛盾**。全系统事件溯源+CQRS+校验门微服务群+Neo4j+渲染 Worker 集群+离线计算集群，是七份回复中最重的架构，却给出"总计约 18–22 人月"——其中"前端与渲染 3 人月"覆盖教研后台+扫码小程序+渲染管线，是数量级错误，对照四份严肃方案的 67–174 人月低估约 4–8 倍。估算不可信即方案不可信。
- 其他问题：Neo4j 无任何规模论证（恰犯三个强参考模型共同否决项）；应用层抛异常冒充"物理阻断"（弱于 MD 触发器/GPT 角色权限两个层级）；GPT 明确警示"不建议全系统事件溯源"正中其设计；"完全满足所有 M 级需求"的断言无任何追溯证据；"不可见数字水印"追溯在印刷-拍照链路上可靠性存疑。
- 仅摘取：**AI 评分重判成本爆炸警示与增量重判策略**（其余模型未明示的真实运维风险）；评分逻辑以容器镜像 digest 版本化。

#### DB —— 局部事实参考，采纳

- 非架构方案，是对课标/教材事实的修正，两点对架构有真实校准价值：
  1. 2022 版新课标 2022 年秋已实施，2026 秋是**全年级统一换成配套新教材**（不是当年才改课标）；数学"一标多本"，各版本差异**不止知识点顺序**，还有单元合并拆分、例题、综合实践设计——直接影响 S1"教学进度日历"的建模粒度：必须按教材版本建模"单元结构映射"，不能只做知识点重排。
  2. **语文为全国统编唯一版本**——第二年语文上线后"教材版本"维度对语文为空，S1 的版本映射本质是数学（及后续英语）问题。
- 局限：无来源引用，逐年替换细节建议作为待核实假设采纳。

#### DS —— 局部算法参考，有限采纳

- 仅为 FSRS 排程器的科普片段（DSR 三要素：稳定性 S/难度 D/可提取性 R；v4.5 含 17 参数；v6 可个性化调参），且原文末尾截断。
- 价值：为 R-Z-07 复习排程的"策略接口"提供一个现成的 v2 候选实现。**注意适配缺口**：FSRS 为闪卡场景设计，复习对象迁移到"带知识点结构与错误类型归因的数学题"需要改造，不能照搬。

## 第二部分：共识分析

### 2.1 强共识（多模型一致，且 MD/FB/GPT 三个强参考模型一致——可直接定为架构公理）

**A. 顶层形态与主线**

1. **系统形态从简**：模块化单体（或核心单体+少量独立伸缩执行器）起步，明确拒绝微服务全家桶。理由三方独立给出且一致：首年规模远不需要，微服务会撕裂内容/作答一致性。（GK 骑墙、GLM 例外，不影响头部一致性。）
2. **同一架构主线**：**内容不可变 + 作答事件化（append-only）+ 一切派生结论（分数/参数/掌握度/报告）可重算、方法可整体替换、新旧并存**。五份方案各自独立推出同一原则（MD 表述最精炼："方法演进只换视图、不动数据"）。这是全部设计的公理级底座。

**B. 母题与实例**

3. **母题 = 声明式结构化文档（YAML/JSON + Schema 约束）+ 受限安全表达式语言**（CEL 类或自研：纯函数、无 IO、无循环、确定性），5/5 一致否决纯代码模板（不可审阅、有安全面）与纯文本模板（表达不了约束与答案推导）。
4. **教研审阅 = 表单 + 实时实例预览 + 边界样例枚举**，审"渲染出的题的行为"，不审定义文本；DSL 仅是存储格式（5/5，措辞近乎相同）。
5. **实例身份内容寻址**（hash(母题版本 + 规范化参数 + 引擎/依赖版本)）+ 参数持久化 → 可复现性由构造保证而非纪律（5/5）。
6. **难度影响声明**：槽位/参数显式标注是否影响难度，影响者变动触发难度重估（MD 的 `difficulty_relevant`、FB 的 `difficulty_sensitive`、GPT 的 `difficulty_effect`，同一设计三种命名）。

**C. 校验门**

7. **校验门 = 验证器插件（统一契约：三/四态结论+证据+置信度+版本+成本）× 版本化门策略（按学科×产物类型配置）× 管线/DAG 编排（廉价先行、硬门短路）**；新增学科 = 新配置+新插件，框架零改动（5/5）。
8. **"物理上无法入库"必须落到数据库层**：MD 门证书+触发器、FB staging/published 分区+单一写入方、GPT authoring/serving 分 schema+角色权限——三种实现、同一原则；GK/GLM 的应用层方案被一致比下去。
9. **数学验算双实现/独立求解器**（SymPy 类 CAS，与生成器不共享代码，防"生成器的 bug 验证它自己"）+ 变式可解性穷举/采样（MD/FB 明确提出，GPT/GK 同方向）。
10. **每次校验留痕**（过了哪些门、结果、证据、校验逻辑版本、时间、成本），可审计（5/5）。

**D. 参数与数据飞轮**

11. **先验/实测并存、来源可辨；融合 = 贝叶斯收缩/精度加权**（样本少贴近先验、多则由数据主导，连续切换而非断崖）；**练习/诊断/测量分场景独立估计、禁止混估**（MD/FB/GPT 高度一致）。
12. **估计器/评分器 = 可整体替换的版本化批处理**：新方法产生新快照/新 run，旧值全保留，"当前指针"是视图；历史作答可在新评分逻辑下重判（5/5）。
13. **掌握度轻量起步**（Elo/BKT 类）+ 在线轻量/夜间权威双轨，后续可换 IRT/深度模型（4/5）。

**E. 知识体系**

14. **图谱演进机制**：稳定身份（标注指向 node_id/编码而非行 ID）+ 编码语义一经发布冻结、只可软废弃+supersede 链 + 有效期/graph_release 版本 + as-of 历史视图（5/5）。
15. **多维并行**：维度（知识点/认知过程/载体类型）是一等实体，题目标注 =（维度， 编码）对集合，不塞进单一树（MD/FB/GPT 明确同构）。
16. **错误类型 = 独立数据资产**（身份、定义、判定规则版本、证据计数），可被多题引用、挂接知识点、由真实数据修正（5/5）。

**F. 组装、渲染与追溯**

17. **三用途同一组装引擎、同一题库，差异全部收敛为版本化约束集/Profile**；硬约束+软目标；组装确定性（快照+策略版本+种子）可复现可审计（5/5，直接呼应 R-Z-01）。
18. **离线/在线同源**：卷 Spec/FormManifest/PaperDocument 不可变中间态为枢纽，静态批渲染与在线实时双出口（5/5）。
19. **追溯编码**：卷码（QR）+题短码+库内"卷→题→版本"映射表，作为作答回流入水口（5/5）；码内不放明文实例信息（FB 防爬库、GPT 签名 token）。
20. **复习排程 = 可整体替换的策略插件**，v1 简单算法起步（5/5 方向一致，具体算法各异——见弱共识）。

**G. 横切**

21. **多学科 = 学科包 SPI**（数据+配置+有限注册点插件），核心零学科特判；**首年即用"玩具/影子第二学科"全流程实证扩展性**（5/5，连验证手法都趋同）。
22. **AI 网关统一收口**：任务分级路由（关键任务强模型、高频任务弱模型）+ 每次调用台账（模型/prompt 版本/token/成本/关联产物）→ 单题全生命周期成本可核算；学生 PII 在网关前剥离（5/5）。
23. **作答 append-only + 开放列式归档（Parquet）支撑十年重算**（5/5；管道重量级有分歧——见分歧点 3）。
24. **假名化 + PII 独立隔离库 + 家长授权前置 + 最小化采集 + 不组织跨用户排名**（MD/FB/GPT/GK）。
25. **过程题首年诚实降级**：结构化分步录入/答题区 + 拍照手写识别仅作录入辅助+人确认；AI 评分经"公开基准验证→影子运行→抽检伴随→灰度"上线（MD/FB/GPT 措辞接近）。
26. **公认 Top 难点**：R-Q-05 目标不变的可证明性、S2 手写批改精度、冷启动难度先验质量（MD/FB/GPT/GK 一致）。

| W8 | 查重组合 | 公共底：指纹+向量双路；增量：GPT"解题结构指纹"第四级、FB"外部真题指纹服务（法务开放项）" | D3 |
| W9 | 工程量估算 | MD≈89 / FB≈80 一档；GPT 130–174 / GK 90–140 一档；GLM 18–22 离群失真 | §4 |

### 2.3 重大分歧点（3 个，必须决策）

1. **图谱存储（PG vs 图数据库）**——最尖锐的选型分歧。PG 派（MD/FB/GPT）给出相同规模测算（节点千级、语文混淆边数千至万级、查询 1–3 跳），递归 CTE+闭包表足够；图库派（GLM）未回应规模论证。**评判：PG 派论据明显扎实；GK/GPT 预留的"异步复制到图引擎"是可接受的远期演进口。**
2. **组卷求解器（CP-SAT vs 轻启发式）**——MD/GPT 认为诊断/测量的硬约束组合（孤立题、双向细目表计数）必须成熟求解器；FB 认为小卷启发式足够。**评判：MD 的折中（离线完整 CP-SAT、在线候选预算+启发式修补）最具可操作性，且与"离线/在线同源"自洽。**
3. **数据管道重量级（轻 PG+Parquet vs Kafka+Iceberg）**——MD/FB 以首年百万条量级刻意保守；GPT/GK 以十年资产主张早建湖仓，但 GPT 自己也承认 Iceberg catalog 有开销。**评判：首年采轻方案、预留事务外箱接口，数据量到位后再演进（MD 已内置"DuckDB→ClickHouse"演进口）。**

### 2.4 独有贡献地图（综合时必须吸收的）

- **MD 独有**：门证书 DB 触发器；CI 玩具学科包+禁止 import 学科包的边界守卫；精度（1/方差）加权收缩公式；testlet 估计呼应 R-Z-06；年度全量重放演练制度化；M2 组装抽象 spike；完整 DSL 示例。
- **FB 独有**：拆母题纪律；预渲染专项卷库存；练习数据暴露偏差警示；"解题技能集合恒等"校验；AQL 加严抽检；二维码防爬库；外部真题查重=法务开放项；题库容量 vs 周更消耗矛盾与缺口预警；R-K-05 治理视角；50 真实母题冻结 DSL v1；先验即贝叶斯先验的样本量三档（200/1000）。
- **GPT 独有**：需求内在矛盾（20 题 vs ≥3 题）；曝光互斥范围质疑；VariantCertificate/UNPROVEN；置信度四层分离；authoring/serving 角色分离；查重第四级结构指纹；relation_type 元数据（directed/transitive/acyclic）；标注记录 graph_release；事务性曝光预留；不可行必须返回冲突原因；层级模型借力稀疏实例；ActiveModelPointer；DatasetManifest 永久标签；可执行验收指标章；四项业务确认清单；WASM 签名沙箱（远期）。
- **GK 独有**：QTI 互通；组装 rationale；公平性监控落点；心理测量顾问。
- **GLM 摘取**：增量重判防成本爆炸；评分逻辑容器镜像 digest 版本化。
- **DB 提供**：课标时间线与"语文统编单一版本、数学一标多本且差异不止顺序"的事实校准。
- **DS 提供**：FSRS（DSR 模型、v6 个性化参数）作为排程 v2 候选实现。

## 第三部分：最终架构决策（整体图景）

> 决策原则：**以 MD 为架构基线，吸收 FB 的全部专项洞察与 GPT 的全部分析性发现/验收标准，按 §2.3 仲裁三处分歧，GK/GLM 仅取局部，DB/DS 作事实与算法校准。** 以下每个决策点标注〔采纳来源〕。

### 3.0 一句话总纲

> **一个学科无关的模块化单体，围绕"三本只增不改的账"（内容版本账、作答事件账、校验签发账）运转；母题是声明式数据，实例是内容寻址的不可变资产，入库必过策略化校验门（数据库层强制），三用途组卷是同一引擎对三套版本化约束集的确定性求解，参数/掌握度/报告全是作答事件之上可重算的视图，学科差异全部收敛在 SubjectPack 内。**

### 3.1 系统形态与分层

```
接入层    微信小程序（家长/学生）            教研工作台（Web，非程序员）
────────────────────────────────────────────────────────────────────
应用层    练习 │ 诊断 │ 测量 │ 扫码批改(S2) │ 试卷服务(S1) │ 报告
────────────────────────────────────────────────────────────────────
领域核心（学科无关，零特判；CI 扫描禁止 import 学科包）
  题库域   母题DSL / 实例 / 版本 / 谱系 / 素材 / 解析
  知识域   多维图谱 / 类型化边 / 错误类型资产
  组装域   引擎 + 约束集Profile(练习/诊断/测量) + 曝光账本 + 复习排程
  校验域   门策略 / 验证器注册 / 门证书 / 抽检队列(AQL加严)
  评分域   评分器插件 / 分步Rubric / 错误推断(证据+置信度)
  估计域   参数估计 / 掌握度 / 覆盖缺口盘点 / 退役建议
  渲染域   PaperDocument中间态 → 版式模板 → PDF试卷+解析册
────────────────────────────────────────────────────────────────────
学科扩展层 SubjectPack：数学包(首年) │ 语文影子包(首年验证) │ 语文包(第二年)…
────────────────────────────────────────────────────────────────────
数据层    PostgreSQL(权威，JSONB+分区+触发器) │ 对象存储(试卷/素材/Parquet归档)
          Redis+任务队列（校验/渲染/估计作业化；预留事务外箱接口）
横切      AI网关(L0–L3分级/成本台账/谱系) │ PII保险库+同意 │ 审计哈希链
```

**部署决策**：首年 1 个单体应用 + 3 类可独立伸缩的执行器（校验/验算 Worker、渲染 Worker、估计批处理），托管容器即可。〔采纳 MD；否决 GPT 的 K8s+六部署单元、GK 的微服务倾向、GLM 的微服务群〕

**技术栈决策**：**Python 单一语言**（FastAPI + SymPy 验算 + NumPy/statsmodels 估计同语言，领域核心无跨语言缝）。〔采纳 MD；否决 GPT 的 Kotlin 核心+Python 工人的双语言方案——14 人以下团队不配拥有两条语言战线〕

### 3.2 逐域决策

#### D1 母题载体：声明式 DSL + 安全表达式 + 建模纪律

- 母题 = YAML 文档，JSON Schema 约束、Linter 静态检查、自身版本化。六大块：`objective`（知识点集/认知层级/多点关系声明）、`slots`（类型/取值域/槽间约束/**difficulty_relevant 标志**）、`variation_axes`（六变式轴→槽子集映射）、`presentation`（无逻辑插值模板+图形 DSL）、`answer_program`（安全表达式+学科函数库）、`distractor_rules`（干扰项=f(错误类型, 槽值)，选项绑定 error_type_id）。〔MD §3.2 为主，FB/GPT 同构〕
- 表达式语言：自研极小求值器或 CEL——纯函数、无 IO、无循环，保证终止与确定。〔FB/GPT；否决 GPT 首年的 WASM 沙箱，列为远期学科函数库扩能选项〕
- **写入建模规范的两条纪律**：①凡改变考查目标的参数不得作为母题内变式维度，**必须拆母题**〔FB 独有，R-Q-05 可证性的根基〕；②客观题优先"按构造必然合法"的生成器设计，而非事后穷举补救〔GPT〕。
- 教研审阅：表单编辑器 + 实时实例预览（拨槽即见题）+ 按轴抽样 20 例 + 边界实例自动枚举；签发在 UI 完成、入谱系。〔MD/FB/GPT 共识，MD 表述最全〕
- DSL v1 冻结方式：前 2 个月用 50 个真实母题（覆盖三年级数学全部题型）驱动设计并冻结语法。〔FB〕

#### D2 实例化与身份：内容寻址 + 池化物化（仲裁 W3）

- 实例身份：`instance_id = H(母题版本digest, 规范化参数, 学科包digest, 生成器digest, 词库digest, locale)`；使用定点/分数运算避免跨语言浮点漂移；同一实例键唯一约束，重复请求返回同一实例。〔GPT 的 digest 链最完整，采纳；MD/FB 同原则〕
- **物化策略仲裁：采纳 GPT 的折中**——不预生成全量组合（组合爆炸），**在线与组卷只消费"已发布实例池"**；池由批任务按生产计划预生成并过校验门；库存不足（覆盖缺口盘点预警）异步补池；**实例物化时连同渲染文本快照入库**〔FB 的正当要求：复现不依赖引擎重放、校验门有确定受检对象〕。用户请求链路中永不临时调用大模型出题。
- 实例数量不封顶（R-Q-01）由"参数空间声明+按需物化"满足，不占存储。

#### D3 校验门：策略×插件×证书，数据库层强制（仲裁 W7/W8）

- 三要素：**GatePolicy**（学科×产物类型的版本化有序验证器链，含阻断/警告/抽检比例、超时降级）×**验证器插件**（统一契约 `validate(artifact, ctx) -> {pass|fail|review, evidence, confidence, validator_version, cost}`）×**产物状态机**（draft→quarantined→published→retired）。〔MD 为主，FB/GPT 同构〕
- **"物理无法入库"采纳 MD 方案**：发布事务必须持门证书（全部阻断项通过），数据库触发器强制 `published_at` 非空必伴随合法 `gate_certificate_id`；辅以 GPT 的逻辑分区——authoring/serving 读视图分离、组装服务只读 serving。验收测试含"绕过发布服务直写必须在 DB 层失败"。〔GPT 的 schema+角色方案为等同备选，实施时二选一，推荐触发器优先——改动小、与 MD 基线一致〕
- 编排器仲裁（W7）：**普通任务队列**（Redis+Dramatiq 类）异步编排，廉价验证器先行、阻断短路。〔采纳 MD/FB；否决首年 Temporal——人工抽检等待用状态机+队列即可表达，预留接口〕
- 数学验算三层：①**双实现独立重算**（验算器与实例化引擎不共享代码，SymPy 独立实现）〔MD/FB 共识〕；②变式可解性：可枚举域穷举、连续域属性采样（除零/选项重复/干扰项等于正解等退化检查）〔MD/GPT〕；③目标不变：objective 声明为槽值显式函数，沿单轴变式批次机器核验目标签名不变 + 独立求解器输出"解题技能集合"恒等校验〔FB/GPT〕；不可机器判定部分 → 强模型裁判 + 人工抽检，**结论状态区分"已认证/UNPROVEN"**〔GPT〕。
- 查重四级（W8）：规范化精确摘要 → 结构指纹（识别只换数字）→ MinHash/n-gram → 语义向量；高相似进人工裁决（裁决产生结论而非跳过硬门）。外部真题/教材相似度 = **待法务共同定义的开放项**（第三方指纹服务+人工抽检兜底）。〔GPT 四级为主，FB 法务警示采纳〕
- 抽检：按可配置比例分层送检；**不合格自动对同母题/同批次升级采样率（AQL 加严）**；结论回流验证器阈值调优数据集。〔FB/MD〕
- 留痕：gate_run + verdict 全量落库（策略版本、各验证器版本、证据、成本、耗时）。

#### D4 参数标定：三本账上的可重算视图

- 存储：`item_param(item_version_id, purpose_scope, source, params{difficulty, discrimination…}, sample_size, method_version, as_of)`；`source ∈ prior_rule / prior_expert / measured_*`；`purpose_scope ∈ practice / diagnosis / measurement`；开放题按评分维度分别估计。〔MD §5.2 为主〕
- **融合策略：先验即贝叶斯先验的收缩估计**——默认配置采 FB 三档（n<200 用先验；200–1000 先验与实测按精度加权收缩；>1000 用实测），机制即 MD 的 1/方差加权；融合策略本身是配置、可整体替换。
- **场景纪律**：估计器按场景独立取数独立产出；**练习场景数据因自适应组卷存在暴露偏差，只用于粗校准与差题预警，正式标定以诊断/测量为准**。〔FB 的关键统计学警示，MD 的"禁止混估"同向〕
- 可替换性：估计器 = 纯批处理作业，输出契约固定；首年 CTT（正确率/点二列）+ 经验贝叶斯收缩 → 次年 Rasch/2PL（预留锚题等值）；题组相关性用 testlet 变体/聚类稳健标准误。每次估计运行绑定 model_version+代码 digest+**输入数据快照**+图谱 release；`ActiveModelPointer` 切换线上版本，历史报告永远引用当时模型。〔MD/GPT〕
- 掌握度：Elo/加权正确率起步，在线轻量增量（内存态）+ 夜间批处理权威修正的双轨；可换 BKT/IRT。诊断报告"结论置信度"= 当前估计器后验输出；**允许输出"证据不足"**。〔FB/GPT〕
- 重判（R-D-05）：新 scorer 版本重放历史事件、写平行 score_run，原序列不动；**采增量重判策略防全量重跑成本爆炸**〔GLM 唯一被摘取点〕；评分逻辑版本含容器镜像 digest。
- 制度设计：**每年一次全量重放演练**（用新评分/新估计重算全历史），证明"可重算"不是口号。〔MD/FB〕

#### D5 知识图谱：PostgreSQL 单库（仲裁 W1——否决图数据库）

- **决策：纯 PostgreSQL**，不引入 Neo4j 等图数据库。理由（三强一致）：节点千级（语文混淆边亦只万级）、查询 1–3 跳浅遍历、团队已强依赖 PG、十年尺度每多一套存储多一份数据主权与运维负担。〔MD/FB/GPT；否决 GK 混合存储与 GLM 图库方案〕
- 表结构：`kp_node(node_id, dimension, code, title, std_anchor, status, valid_from/to, supersedes_id)` + `kp_edge(src, dst, rel_type, attrs, provenance)` + `relation_type` 元数据（directed/transitive/acyclic）〔GPT〕+ `kp_closure` 传递闭包扁平表（图谱变更增量刷新；组卷/报告只读扁平表，递归 CTE 仅管理查询）+ 高频路径整图 MB 级快照加载内存、按 graph_release 版本缓存。〔MD/FB〕
- 演进纪律：code 一经发布冻结语义，修订 = 新编码+旧编码 deprecated+supersede 链；**标注指向稳定 node_id 且记录标注时的 graph_release**；查询支持"按当时图谱解释 / 映射到当前图谱"双模式〔GPT〕；演进操作走审批流——这是治理问题，技术管不住，需组织流程配套〔FB〕。
- 多维并行：dimension 一等公民；语文形近/音近/义近 = confusable 类边的 attrs，数千条规模无压力（R-K-04）。错误类型独立资产表（定义/判定规则版本/证据计数），`error_type_kp` 挂接知识点。

#### D6 组装引擎：一引擎三 Profile，离线 CP-SAT + 在线启发式（仲裁 W2/W5）

- **仲裁采纳 MD 折中**：候选筛选（题库快照×发布状态×用途许可×曝光历史）→ **离线出口跑完整 OR-Tools CP-SAT**（硬约束求可行解+软目标优化；测量双向细目表计数约束 CP-SAT 直接表达）→ **在线出口毫秒级用"候选预算装填+加权启发式修补"**。同一引擎同一题库，Profile 与时间预算不同而已——这正是"题是数据，卷是视图"。FB"小卷不需要重型求解器"的判断在在线侧成立，但测量细目表与诊断硬约束组合仍要 CP-SAT 兜底并给出**不可行时的冲突原因**（不得静默放松）〔GPT〕。
- 三用途 = 三套版本化约束集 Profile（练习/诊断/测量），覆盖：目标正确率区间（按 P(correct|item, 学生或 cohort 参考分布, 场景) 计算，含参数不确定度惩罚项〔GPT〕）、梯度单调（先修闭包+难度序列）、新学/复习/易混淆配比（消费 confusable 边）、曝光互斥、诊断三硬约束（孤立题强制+每点≥3+关系声明核验）、题组≤6。
- 确定性：给定（快照 id, Profile 版本， 种子）结果唯一，全程留档可复现。
- 曝光账本双轨：静态渠道按"渠道×年级×版本×周"队列键控〔MD/FB〕，在线按学生；**事务性曝光预留**处理并发冲突〔GPT〕。**向业务明示能力边界**：社交媒体公开 PDF 只能保证批次/周次级不重复，个人级不重复需记录家庭领取〔GPT 发现，列入 §5 开放项〕。
- 求解失败输出结构化缺口报告 → 直接馈送覆盖缺口盘点（知识点×认知层级×用途三轴热力图），"组不出卷"成为生产排期自动信号。〔FB/MD〕
- 复习排程（W5）：纯函数策略接口 + 版本化 ReviewPolicy 产出可重建 ReviewQueue；**v1 = 固定间隔表（1/3/7/21 天）或 SM-2 类**；**v2 候选 = FSRS**〔DS 片段提供的 DSR 模型与 v6 个性化参数〕——注意 FSRS 为闪卡设计，需改造以挂接知识点结构与错误类型归因，不可照搬。
- 自适应（R-Z-08）：首年不做，但会话抽象为 `next_item(session_state)` 策略接口，次年换 CAT 不动会话框架。

#### D7 渲染与追溯：中间态同源 + HTML/CSS 首年（仲裁 W4）

- **仲裁采纳 MD/FB 的 HTML/CSS 路线**：PaperDocument（JSON 中间态：实例引用+版式提示，内容-样式分离）→ HTML/CSS+KaTeX+图形 DSL→SVG → 无头 Chromium → PDF 试卷+解析册。决定性理由：品牌模板 = 页面模板+CSS+字体包，设计师可直接迭代（R-N-05）；Typst 的 HTML 输出仍为实验能力，其"打印 Typst+在线 React 双渲染器"反而多维护一个出口。**Typst 列为排版质量备选路线，首年后评估**。〔否决 GPT/GLM 的 Typst 首年方案；GPT 的 Render IR 概念由 PaperDocument 吸收〕
- 周更批处理：（年级×教材版本×教学周）→ **版本化教学进度日历**→已学范围→组装→渲染→发布（paper+paper_item 不可变落库，对象存储内容哈希寻址）。**进度日历必须按教材版本建模"单元结构映射"而非仅知识点顺序重排**〔DB 事实校准〕；语文上线后无教材版本维度〔DB〕。
- 追溯编码：每卷唯一卷码+QR（码内只含卷 Spec ID+校验位，**不含实例明文，防爬库**〔FB〕）；每题印刷带纠错短码（或签名 placement_token〔GPT〕）映射 item_version_id；paper_item 渲染时固化"卷→题→版本"。
- S2 针对性练习发放：**按错误类型预渲染专项小卷库存，诊断出类型即查表发放**——不做按人实时渲染。〔FB 独有，决定 S2 单位经济性〕
- 解析册：按错误类型组织（"你可能这样想"）+完整分步过程；"作答后才展开"在线端呈现层开关。

#### D8 批改评分与错误推断：首年结构化降级（强共识）

- 客观题：确定性评分；数学等价走符号比较（分数化简/单位换算/数值容差），非字符串匹配。
- 过程题：**首年输入形态为结构化分步录入/答题区**（选择/填空步、页面定位标记、固定答题框），把评分收敛为确定性问题；拍照手写识别仅"识别建议+人确认"的录入提效，**不承诺任意手写草稿的全自动分步判分**。〔MD/FB/GPT 强共识；GK 偏激进不采纳〕
- AI 评分上线四步：公开基准验证（R-G-06）→ 影子运行 → 抽检伴随 → 灰度。〔MD〕
- **置信度四层分离**：图像识别置信度 / 评分置信度 / 错误类型推断置信度 / 掌握结论置信度，不得混为一个"AI 置信度"；低置信自动转人工队列。〔GPT 独有，采纳〕
- 错误推断：选择题 = 选项→错误类型的确定映射（模板层 distractor_rules 绑定）；开放题 = 维度得分模式→错误类型规则表；推断输出带置信度、规则版本化；**多题证据贝叶斯累积，报告置信度即后验**〔FB〕；**"选某项"是证据而非因果结论**〔GPT 的统计学严谨〕；compensatory 题只佐证不定位，定位必须由孤立题完成〔FB〕；真实发生率回流修正规则与证据计数（R-Q-08）。

#### D9 多学科扩展：SubjectPack SPI + 首年实证

- 核心平台零学科特判；学科差异全部收敛到 SubjectPack：DSL 槽位类型/函数库、评分器、验证器、图形渲染器、图谱数据、错误类型体系、约束集预设、卷面模板。〔MD 清单最全〕
- **首年即自证**（R-N-03 不停在口头）：①CI 扫描核心域代码，禁止 import 任何学科包，边界渗漏即构建失败〔MD〕；②CI 内跑"玩具学科包"（或 Q4 语文影子包：20 母题+一材多题+形近音近混淆+简答评分维度+来源许可+语文门策略）走全流程〔MD/GPT/FB 趋同〕；验收标准：核心库无 schema 迁移、数学代码无修改、组装引擎无新分支〔GPT〕。
- **诚实边界写入验收口径**："新增学科=零新代码"的可实现形态是"核心零改动、新增收敛于插件注册点"；全新作答模态（如英语语音评分）仍需新插件，但插件经稳定接口部署、不改核心。〔FB/GPT 共同重解释，列入 §5 开放项〕

#### D10 AI 网关与成本治理

- 全部 LLM 调用经内部 AI 网关，**L0–L3 分级**：L0 不用 AI（实例化/验算/规则评分）、L1 弱模型（标签建议/抽取/查重初筛）、L2 强模型（出题草稿/语义审题/事实核查/开放题评分）、L3 高风险复核（双模型交叉或 AI+人工）。〔GPT 细化 MD 的强弱路由，采纳〕
- 每次调用记台账（任务/模型精确标识/prompt 版本/token/成本/关联产物 id/是否含脱敏作答）→ 按 item_revision 归集单题全生命周期 AI 成本；谱系引用台账 id；PII 在网关前剥离；关键任务双供应商预案。

#### D11 数据底座与合规：轻管道首年（仲裁 W6）

- **仲裁采纳 MD/FB 轻方案**：`response_event` 大表按月分区 append-only（数据库权限禁 UPDATE/DELETE + 定期哈希锚定入审计链）；字段全要素（事件 id、匿名学生 id、item_version_id、场景、**原始作答载荷 JSONB**、耗时、评分轨迹、错误推断+置信度、testlet_id、会话 id、时间戳）。**每日增量导出 Parquet 至对象存储 + schema 注册表**——十年可用的本质是"原始数据不依赖任何单一数据库厂商的开放归档"。〔否决首年 Kafka/Iceberg——GPT 自己也承认其开销；**预留事务外箱接口**，分析侧首年 DuckDB、数据量到位后演进 ClickHouse（MD 已内置演进口）〕
- 合规：student_alias_id；姓名/联系方式入独立 PII 保险库（分离 schema、列级加密、白名单、独立审计）；家长授权记录前置（版本/范围/时间/撤回）；采集字段清单化；**代码层不提供跨用户排名查询路径**；远期同龄定位只在 k 匿名聚合之上计算；扫描件姓名 redaction 后再入模型。〔MD/GPT〕
- 审计：内容谱系+门证书+签发记录+组装留档+评分版本+AI 台账构成完整回溯链；审计日志哈希链防篡改；业务审计账本独立于运维日志（OpenTelemetry 只管技术运行层）〔GPT〕。
