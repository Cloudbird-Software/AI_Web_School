# 模型基准赛（Model Bench）v1 —— 附录 D 完整版
> 目的：用可执行数据回答"哪个模型干哪类活最划算"，产出 .agent/routing.yaml。
> 保密纪律：本目录必须放**私有仓库**或独立私有路径，禁止进入公开仓库/公开镜像（题集泄入训练语料即基准失真）。每季度轮换 1/3 题目，轮换记录存 rotation-log.md。

## 1. 任务集（30 题，6 类 × 5 题）

### A 类：规格理解（测"读得懂规格吗"）
| id | 任务 | 输入 | 评分（可执行） |
|---|---|---|---|
| A1 | 读模块规格写接口骨架 | 一个真实 L2 模块规格（500 行） | 生成的接口与参考骨架符号级比对：函数名/签名命中率 ≥90% |
| A2 | 规格问答 | 规格 + 5 个细节问题（答案在文中） | 5 题答对数（关键词精确匹配） |
| A3 | 找规格矛盾 | 两份故意埋了 2 处矛盾的规格 | 找出矛盾数：2/2 满分，多报扣分 |
| A4 | 写验收清单 | 模块规格 → 验收标准清单 | 与参考清单的覆盖率（裁判模型评分，见 §3） |
| A5 | 识别镀金 | 给一段实现计划，其中 2 项超出 non_goals | 识别 2/2 满分 |

### B 类：代码实现（测"照规格写得出吗"）
| id | 任务 | 评分 |
|---|---|---|
| B1 | 实现内容寻址哈希函数（规范化 JSON+sha256，给契约） | 隐藏测试 12 例全过=100，按过例比例 |
| B2 | 实现产物状态机守卫（draft→quarantined→published→retired + 门证书校验） | 隐藏测试 15 例 |
| B3 | 实现闭包表增量刷新（给表结构与事件） | 隐藏测试 10 例 |
| B4 | 实现 YAML DSL 校验器（给 schema 与 20 个正/反例） | 20 例判对率 |
| B5 | 实现组卷软目标打分函数（给权重与公式） | 隐藏测试 8 例 |

### C 类：缺陷修复（测"找得出 bug 吗"）
| id | 任务 | 评分 |
|---|---|---|
| C1 | 闭包表刷新的 off-by-one（埋入） | 定位+修复且全测试过 |
| C2 | 哈希规范化漏了浮点定点化（埋入） | 同上 |
| C3 | 门证书校验可被空串绕过（埋入） | 同上+必须补回归测试 |
| C4 | N+1 查询（埋入 ORM 代码） | 修复且查询数断言过 |
| C5 | 时区 bug：事件按本地日期分区（埋入） | 修复且跨时区测试过 |

### D 类：测试编写（测"会验证吗"）
| id | 任务 | 评分 |
|---|---|---|
| D1 | 为给定函数写单测 | **mutation 击杀率**（注入 8 个变异体，被杀比例） |
| D2 | 写 property-based 测试（给不变量描述） | 能抓住 3 个埋入反例 |
| D3 | 从 OpenAPI 片段生成契约测试 | 覆盖全部字段约束 |
| D4 | 制作黄金样例（给母题 DSL，产出期望实例+哈希） | 与参考输出逐字节一致 |
| D5 | 从 bug 报告写回归测试 | 测试在修复前红、修复后绿（双跑验证） |

### E 类：精确输出（测"格式可靠吗"）
| id | 任务 | 评分 |
|---|---|---|
| E1 | 按 JSON Schema 生成 10 条合规数据 | schema 校验通过率 |
| E2 | 从 ER 描述写 PostgreSQL DDL（含分区/触发器） | 可执行+约束存在性检查 |
| E3 | 写 OpenAPI 片段（给端点描述） | openapi 校验器通过 |

### F 类：长上下文检索（测"上下文里找得准吗"）
| id | 任务 | 评分 |
|---|---|---|
| F1 | 在 30 页规格库中找"某场景适用哪条宪法" | 命中正确条款 id |
| F2 | 找两份规格间的矛盾（同 A3 但分散在 5 万 token 中） | 找出率 |
| F3 | 需求 id → 模块追溯（"R-Q-05 由哪些模块承载"） | 与参考清单一致率 |
| F4 | "哪些文件涉及概念 X"（给代码库快照索引） | 查全率/查准率 |
| F5 | 带引用的问答（答案须标注 文件:行号） | 答案正确且引用真实存在 |

## 2. 执行

```bash
make model-bench MODEL=<provider/model>   # 对单个模型跑 30 题
# 等价于：python tools/bench/run.py --model <m> --suite tests/model-bench/suite.yaml
```
- 每题 3 次重复（温度默认），取通过率均值；记录 token 消耗。
- 输出：`tests/model-bench/results/<model>-<date>.json`：{task_id, pass_rate, tokens_in, tokens_out, latency}。

## 3. 评分规则
1. **可执行检查优先**：B/C/E 类与 A1–A3、F1–F3 全部由隐藏测试/精确匹配评分，无人工参与。
2. **裁判模型仅用于** A4/D1 辅助/F5 语义等价度；裁判必须与被测模型**不同家族**；裁判 prompt 存 judges/。
3. **成本折算**：每题记录实际 token → 按当时单价算"每通过一次的成本"（cost_per_pass = 总花费 / 通过题数）。

## 4. 产出路由表
`python tools/bench/route.py` 汇总全部模型结果，按任务类计算 cost_per_pass 排名，生成 `.agent/routing.yaml` 的 tiers 建议（diff 形式，人类确认后合入）。
- T0 候选 = S 类任务（A3/B2/C3/F2）通过率 ≥85% 的模型中挑能力最强者（不看价格）。
- T1 = B/C 类通过率 ≥75% 中 cost_per_pass 最低者。
- T2 = E 类通过率 ≥90% 中 cost_per_pass 最低者（通常免费/近免费档）。

## 5. 重跑节奏
新候选模型出现、每 2 个月、或遥测显示某梯队线上表现与基准偏离 >15% 时重跑。
