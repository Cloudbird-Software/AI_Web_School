## 目标说明（≤5 行）
旧 Issue #26 要求"import 后直接 commit 入库并更新 current_version"，这与 A2/D2（未过门不得入已发布区）冲突。本卡重写为**受控导入**：外部内容只能落 draft/隔离区，必须先许可登记，再经母题化/改写与校验门才能发布。

## 验收标准（逐条可执行）
1. 导入管线阶段化：解析 → schema 校验 → 许可登记校验（未登记即拒绝）→ 落 draft → 人工/自动母题化 → 校验门 → 发布，各阶段幂等且可重入。
2. CLI 支持 `--dry-run` 与 `--commit`；`--commit` **不能**直接产生 published 行（测试实证）。
3. 导入报告：新增/跳过/失败明细写入 `out/import_reports/`，含拒绝原因。
4. 幂等：同一源重复导入不产生重复内容（复用 W5 的 content_digest 查重）。
5. 测试：跳过许可登记 → 失败；跳过门直接置 published → 失败；正常路径可完成。
