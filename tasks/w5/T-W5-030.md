## 目标说明（≤5 行）

issue #34 §十要求的技术验证 spike：证明 baml-go runtime + sqlc + .baml 函数在本地与 CI 都能走通"生成→golden test→gate"闭环，为 T-W5-031 骨架与 W6 操作员/评价者 harness 扫清工具链风险（上游 #3690 等 codegen 边角问题在此暴露）。

## 验收标准（逐条可执行）

1. `baml generate`（或等价 CLI）产出 Go client，`go build ./...` 与 `go vet ./...` 全绿。
2. golden test：修改 .baml prompt（哪怕一个字符）→ 快照测试红；还原 → 绿（BAML-1 可执行实证）。
3. `sqlc generate` 幂等：对同一 schema/queries 二次生成零 diff（SQL-2 可执行实证）。【本 PR 未做——sqlc 随 T-W5-032 迁移移植落地，见下方 spike 结论】
4. Makefile 提供 `baml-generate` / `sqlc-generate` 目标；CI 能在无 npm 全局环境复现生成物（锁版本）。
5. spike 结论（含上游 bug 规避清单）写回本卡备注或 ADR-0004 附录。

## spike 结论（2026-08-19，实证记录）

- **baml-go runtime 可用**：`@boundaryml/baml@0.226.1` 生成 21 个 Go 文件，经修复后 build/vet/test -race 全绿；go.mod 锁 `github.com/boundaryml/baml v0.226.1`（依赖提案见 ADR-0004 §三，Apache-2.0）。
- **上游 codegen 边角问题实证（规避清单）**：
  1. schema 无 enum 时生成死 import（types 包全部报 unused）——规避：schema 至少含一个真实枚举（本仓用 InteractionTier，A7 四级生产线）。
  2. 无 union 时 unions.go / type_aliases.go 死 import + type_builder.go 缺 fmt import——规避：`make baml-generate` 在 generate 后追加 `goimports -w baml_client`（已固化进 Makefile）；升级 BAML 版本时须复验。
  3. 参数语法是 `name: type`（带冒号）；生成器需 `client_package_name = go.mod module 全名`、`output_dir` 指向模块根，否则内部 import 路径错误。
- **golden 机制落地**：`tools/golden/baml_golden.py`（baml_src 聚合哈希快照，纯 Python、CI 无需 Node）；改 prompt 不刷快照 → `make baml-golden-check` 红（已实证）。
- **sqlc 推迟**：sqlc 依赖 db/queries 与真实 schema，随 T-W5-032 迁移移植一起落地（依赖顺序合理化，本卡验收 #3 移交 T-W5-032）。
- **Go 原生 fuzz 进 gate**：core/webutil FuzzSafeNext（T-W0-010 语义等价移植），`go test -race` 执行种子语料；10s 覆盖引导模式 76 万次执行不变式成立。
