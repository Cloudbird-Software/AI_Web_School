## 目标说明（≤5 行）
D2 声称"门证书由数据库强制"，实际所有内容表的 `gate_certificate_id` 只有非空 CHECK、没有外键，任意字符串即可发布；同时门失败路径写死占位 `cert:none` 而该行从未在迁移中落地，生产首次校验失败即 FK 报错。本卡补 FK 并终结占位行反模式（X11）。

## 验收标准（逐条可执行）
1. 迁移给 `item_version` / `material_version` / `corpus_version` / `passage` 等所有带发布态的内容表补 FK → `gate_certificate(cert_id)`，采用 `DEFERRABLE INITIALLY DEFERRED` 以兼容发布事务顺序。
2. 门失败留痕二选一并写明理由：①`gate_run.certificate_id` 改可空（推荐，语义正确）；②迁移中插入不可删除的系统占位证书行。**禁止**继续依赖测试 fixture 预插（X11）。
3. 测试：以特权连接直写 `status='published'`、`gate_certificate_id='cert_FAKE'` → FK 拒绝；干净库中触发一次 gate fail → `gate_run` 成功留痕且事务不回滚。
4. 既有门相关测试（含 `test_gate_bypass.py`）全绿；`make migrate-check` 全绿。
5. 迁移可逆：downgrade 后 FK 与占位行/可空变更正确回退。
