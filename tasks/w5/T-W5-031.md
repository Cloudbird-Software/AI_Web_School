## 目标说明（≤5 行）

搭出 ADR-0004 定义的 Go 模块化单体骨架：分层、双注册表接口、healthz、import 边界 lint、原生 fuzz。骨架本身不带业务逻辑，但结构约束（X6 学科零特判、D4 双注册表）从第一行代码就由 lint 与测试锁死，避免"先堆功能再补架构"。

## 验收标准（逐条可执行）

1. `go build ./... && go vet ./...` 全绿；`gofmt -l .` 零输出（GO-1）。✅ tools/accept/t_w5_031.sh
2. `go test ./... -race` 全绿（GO-4），至少含 1 个 `func Fuzz*(*testing.F)` 目标且种子语料在常规 go test 中执行（GO/原生 fuzz 进 CI 的事实基础）。✅ FuzzSafeNext（core/webutil）
3. import 边界检查：向 core/ 任何包添加 `import .../packs/...` → lint 脚本红（X6/GO-3 可执行实证）。✅ 脚本内注入违规文件实证红
4. healthz 端点：GET /healthz → 200 `{"status":"ok"}`；异常路径只暴露 error_class，不泄露堆栈/内部地址（对齐 T-W0-010 脱敏语义）。✅ api/api_test.go（含字段最小化断言）
5. registry 双接口（interaction/scorer）存在编译级演示实现，为 D4 提供类型落点。✅ registry/registry_test.go（var _ 编译级断言 + 装配路径测试）
