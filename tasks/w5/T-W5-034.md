## 背景与问题

T-W4-042 交付的 `openapi-v1.yaml` 冻结契约中，`GET /sessions/{session_id}/next` 端点的响应 schema 定义为 `type: object, additionalProperties: true`——这是 FastAPI 对无 `response_model` 路由的自动生成结果，而非精心设计的契约。

该端点实际返回两种形态：
1. **正常取题**：`NextItem` 对象（含 `session_id, round, position, total, item_version_id, interaction_id, content_blocks, options`）
2. **会话完成**：`{"done": true, "session_id": "..."}`

消费者（学生模拟器/小程序团队）无法从当前契约得知响应字段结构，违反 P5（冻结契约应是消费者可凭之开工的确定性规格）。

## 目标说明（≤5 行）

补齐 `/sessions/{session_id}/next` 的响应 schema：在 `components/schemas` 中新增 `NextItem` 引用，使用 `oneOf` 表达两种响应形态；同步更新 `test_api_frozen.py` 的 schema 一致性断言。修改时须在 commit message 中加入 `[FROZEN-APPROVE]` 豁免标记（因涉及冻结契约修改）。

## 验收标准（逐条可执行）

1. `openapi-v1.yaml` 中 `/sessions/{session_id}/next` 的 `200` 响应 schema 使用 `oneOf` 定义两种形态，且 `$ref` 到新增的 `NextItem` schema。
2. `components/schemas` 中新增 `NextItem` schema，字段与 `src/core/session/models.py::NextItem` 对齐。
3. `make accept TASK=T-W5-034` 全绿（契约测试 + 黄金数据集 + 黄金路径快版 + 单元测试）。
4. `check_openapi_diff.py` 相对 `origin/main` 检测到 diff 时退出码非零——验证未豁免时修改被正确拦截。
5. 不 import 任何学科包/学段包（A5/X6）。

## 修复步骤

1. 在 `openapi-v1.yaml` 的 `components/schemas` 中新增 `NextItem` schema。
2. 将 `/sessions/{session_id}/next` 的 `200` 响应 schema 替换为：
   ```yaml
   schema:
     oneOf:
     - $ref: '#/components/schemas/NextItem'
     - type: object
       properties:
         done:
           type: boolean
           const: true
         session_id:
           type: string
           format: uuid
       required: [done, session_id]
   ```
3. 更新 `test_api_frozen.py`：在 `test_impl_schemas_match_frozen_v1` 中断言 `NextItem` 存在于 schema 集合。
4. 验证：`python -m pytest tests/contract/test_api_frozen.py -v` 全绿。
5. 提交时在 commit body 加入 `[FROZEN-APPROVE]` 标记以豁免冻结守卫。
