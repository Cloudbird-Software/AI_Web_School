### #24 W4-1: DB 索引 / 检索 / 性能基线 + 压测 —— 重写
- **诉求成立**：组卷查询在题池增长后必然成为瓶颈，需要索引基线与压测。
- **方案过时**：issue 要求"为 JSONB 字段 objective.kp_set / content.blocks 建 GIN 索引"。当前架构已把知识点关系拆为扁平的 `item_kp` 关联表，组卷不再扫 JSONB；照做会建出无人使用的索引并拖慢写入。pgvector 在当前检索需求下也无必要。
- **裁决**：关闭，重写为 **T-W6-012（组卷查询索引基线与万题级压测）**——先 EXPLAIN 定位真实热点查询，再针对性建索引，以万题级题池压测验证 p95。
- **关闭评论要点**：诉求承接到 T-W6-012；索引方案按现行 schema 重新设计。

### #26 W1-1: 适配器式导入管线 + CLI + 幂等 —— 重写
- **诉求成立**：需要可插拔的导入适配器、dry-run/commit、幂等与导入报告。
- **冲突点**：验收标准写"`--commit` 插入数据并在事务内更新 item 的 current_version_id"，即外部内容可以直接进入已发布区，**违反 D2（未过校验门的产物禁止入已发布区）与 A2**。
- **裁决**：关闭，重写为 **T-W6-008（受控内容导入管线）**——阶段化为"解析 → schema 校验 → 许可登记校验 → 落 draft → 母题化 → 校验门 → 发布"，`--commit` 明确不得直接产生 published 行（有负向测试）。
- **关闭评论要点**：导入能力承接到 T-W6-008，但发布路径必须经校验门。

### #27 W1-3: RACE 适配器（英语） —— 关闭
- **架构冲突**：A1 要求所有内容经统一入库与校验门；把外部数据集的题目直接转成 item_version 相当于用外部质量标准替代自有校验门，且这些题不带母题（无法参与"无限出题"），对 V4 护城河无贡献。
- **合规风险**：RACE 源自中国中高考英语阅读材料，商用许可不明；业务合规红线明确"永不使用教材课文原文、真题原文"。
- **裁决**：关闭，不承接。若未来确需英语阅读语料，走 T-W6-009 的"已登记语料 + 改写"路径，且必须先完成许可登记。

### #28 W1-4: CMRC/DRCD 适配器（语文） —— 重写
- **许可事实**：CMRC 2018 与 DRCD 均以 CC BY-SA 3.0 发布，**可商用**，但有署名（BY）与相同方式共享（SA）义务；SA 义务意味着直接演绎产物可能被要求以同协议开放，需法务确认边界。
- **裁决**：关闭，重写为 **T-W6-009（已登记中文语料接入）**——语料仅作"已登记素材"，经改写/母题化产出自有题目，署名与许可信息全程随行；未登记语料入库必须失败。
- **关闭评论要点**：语料接入承接到 T-W6-009，但走许可登记 + 改写路径，不做原文直导。

### #29 W3-1: 组卷与渲染管线（HTML→PDF） —— 部分完成
- **已有**：`src/core/render/pdf_exporter.py`（HTML→PDF）、`weekly_batch.py`（周报批处理）、paper / paper_item ORM 模型与组卷逻辑。
- **未有**：对外的组卷 API 端点、异步渲染 worker、渲染产物 URL 落库。
- **裁决**：关闭。剩余部分承接到 **T-W7-001（学生端 API 契约）与 T-W7-007（周报推送与 PDF 交付）**。另注意 W5 的 T-W5 系列已修复 PDF 渲染"以文件存在判成功"与 `--no-sandbox` 问题。
- **关闭评论要点**：渲染核心已实现；API/worker/落库承接到 W7。

### #30 W1-2: ASSISTments 适配器（数学） —— 关闭
- **架构冲突**：同 #27。
- **额外风险**：ASSISTments 数据集包含真实学生的作答记录，属第三方个人信息；引入将触发 A6/D7 的个人信息处理义务，与"仅处理自有用户数据"的合规边界冲突，收益（少量数学题）远小于风险。
- **裁决**：关闭，不承接。若未来需要外部作答数据做参数先验研究，必须单独立项并经法务评估。
